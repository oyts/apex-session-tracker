# Apex 战绩记录器

[下载 Windows 测试版](https://github.com/oyts/apex-session-tracker/releases) · [报告问题](https://github.com/oyts/apex-session-tracker/issues/new/choose)

[![Windows tests](https://github.com/oyts/apex-session-tracker/actions/workflows/tests.yml/badge.svg)](https://github.com/oyts/apex-session-tracker/actions/workflows/tests.yml)

目前为 **v14 预发布测试版**，欢迎参与实际游戏测试；已验证内容与未覆盖模式见 [验证范围](VALIDATION.md)。下载 `ApexTracker-Windows.zip` 后解压完整文件夹，运行其中的 `ApexTracker.exe`，不需要安装 Python。

Windows 本地小程序。一个人打开程序，自动捕获小队总结页，即可累计伤害、击杀、助攻、场均伤害与参团率。支持 1／2／3 人统计模式，跨局自动确定参与玩家，卡片换位不会改变统计。保留可自定义的 Ctrl+End 手动补录和图片导入。

本次更新（v14 Beta 7）：删除三张卡片击杀相加的分母兜底，自动采集等待小队总击杀标签和数字显示稳定后再捕获；OCR只采用明确读到的总击杀，未加载完整的候选不自动计入。旧版推算分母失效，个人已确认战绩保留。Beta6功能：总结返回时增加受限的视觉证据比对，忽略排队框、字幕及世界背景；仅比对三张卡片的完整数据区和独立卡面，明确新局和人工归属优先，不按伤害／击杀／助攻相同合并。新增累计及单局参团率、完整小队分母与手动校正，详情见下方说明。Beta5功能：为低置信的击杀／助攻／击倒行增加完整区域双重复核；两次结果必须高置信且与原读数一致，自动入库门槛保持0.94，人工修正保留。Beta4功能：默认请求隐藏Windows窗口捕获提示边框，设置可切换，系统不支持时保留默认边框并继续取帧。Beta3功能：适配外卡加载和同时选人的实际布局，新增每局数据右侧“外卡”标签；保留Beta2窗口捕获、运输船备用入场判断及同片段人工确认同步。v14 基础重构：将比赛、截图证据、OCR版本、身份与最终统计分开；识别加载／选人组合证据来开启新比赛，移除旧跳伞HUD锁。没有看到新局开始也保留总结原图，并进入明确的比赛归属审核。相同数字不参与去重。同一比赛可保留多张原图，手动校正优先，只累计一份最终数据。见 [架构说明](ARCHITECTURE.md)、[研究与覆盖范围](RESEARCH.md)、[版本说明](CHANGELOG.md)。

本机开发目录的 v14 放在 `dist/v14-beta7/ApexTracker/ApexTracker.exe`，根目录“启动战绩记录器.cmd”优先启动它。这样保留正在使用的旧版文件；先关闭旧窗口再启动新版，既有数据仍从默认位置加载。便携包内仍是 `ApexTracker/ApexTracker.exe`。

外卡标签来自本场加载／选人组合证据，随比赛保存；无明确证据的旧记录或独立导入保留未知、不显示标签。标签只作模式区分，当前总计和场均仍包含本次开黑的全部有效比赛，没有自动按模式拆分。请在加载／选人前开始记录，漏开局时总结原图仍保留供审核。

窗口捕获边框：默认勾选“设置 → 隐藏窗口捕获提示边框（系统支持时）”。取消勾选恢复Windows默认行为。Windows未允许、旧系统或其他软件同时要求边框时仍可能显示；本程序不自动批准系统授权，也不修改全局系统设置。

## 启动

运行便携文件夹中的 **ApexTracker.exe**。在本项目中，新版位于 **dist/v14-beta7/ApexTracker/ApexTracker.exe**，也可以双击项目根目录的 **启动战绩记录器.cmd**。打包版已附带 Python 与本地 OCR 模型，不需要另装 Python，也不需要登录账号或调用云端识别服务。

分享给朋友时，复制或解压完整的 `ApexTracker` 文件夹。`ApexTracker.exe` 与 `_internal` 必须放在一起，不能只拷贝一个 exe。

便携包 `dist/ApexTracker-Windows.zip` 只包含程序、运行库及说明。不要分享自己的数据目录、`private-diagnostics`、截图或诊断备份。此界面是参考 [Apex 官方视觉](https://www.ea.com/games/apex-legends/apex-legends) 的非官方工具，面板为代码绘制，不附带游戏角色图片或用户截图作为装饰。

## 第一次使用

1. 显示器默认“自动跟随 Apex（推荐）”，无需选择。特殊情况可在“设置 → 游戏所在显示器”选择“手动：显示器…”并保存。默认截图快捷键为 **Ctrl+End**；直接修改“截图快捷键”输入框，可先点“检查占用”，再“保存设置”。无需提前指定参与玩家。
2. 在主窗口选择 **1 人模式、2 人模式或 3 人模式**，点击“开始记录”，等底部显示“模型已就绪”。
3. 保持“自动捕获总结页”勾选。每局打开“小队总结”页，等待右上“小队总击杀”文字及数字出现并稳定，收到“完整画面已保留”提示后即可离开，无需按截图键。原图捕获后即在后台识别，离开总结页不影响已捕获图片的处理。手动模式则按快捷键，听到保存提示音后继续游戏。
4. 单人／双人模式先保留首局，之后对比各局出现的昵称，自动确定共同的 1／2 位玩家。三人模式在完整、唯一的三个昵称读出后确定全队。名单确定后自动补算此前有效记录。
5. 多局仍无法区分时，可以继续下一局，或者点击“手动确认玩家”，在修正窗口选择参与卡片对应的玩家、将路人选择为 **不统计**，保存后补算之前的有效记录。数字缺失、置信度不足或疑似重复的截图仍需修正确认。玩完点击“结束记录”，已捕获的图片会处理完成后保存；关闭程序同样等待处理，避免丢图。

## 自动记录模式

在主窗口或设置内开启／关闭“自动捕获总结页”。设置保存后会保留，重新打开未结束的会话会恢复自动检测。自动捕获和“可靠数据自动计入统计”是独立设置：可以自动保存总结页，但关闭自动计入、集中手动检查。

默认的“捕获 Apex 窗口”通过 Windows Graphics Capture 绑定唯一游戏窗口，读取客户区。切到其他应用、其他窗口遮挡游戏或移动到另一屏幕时仍可采样，不改变系统焦点。最小化、尺寸过渡或3秒内没有收到新画面会暂停；游戏在后台停止渲染时需要切回。Windows可能显示系统捕获边框。设置可切换“前台屏幕捕获”兼容模式，此时仍按前台窗口位置自动跟随或手动固定显示器，截图前后核对窗口与屏幕。

手动选屏仍按Windows设备标识记住，列表每约2秒刷新；切换主屏不影响设备绑定。断开手动所选屏幕暂停，重连同设备恢复，不擅自切屏。旧配置升级默认开启自动选屏，原手动设备选择保留；若需要固定来源，在设置中选择该显示器保存。更换接口或设备标识改变时，手动模式需要重新选择。自动选屏下快捷键补录也需 Apex 在前台；手动选屏的快捷键仍截取指定整屏，便于特殊情况补录。

升级便携版前先关闭当前旧程序，再解压完整新文件夹或复制整个新版文件夹；不能只替换exe。启动入口不同也会共用默认战绩目录，既有战绩保留。同目录只能运行一个实例；若启动后没有看到底部“v14-beta2”，请检查是否仍在打开旧文件夹中的exe。更新后建议在大厅开始下一局，让新版本看到完整入场过程；已经漏拍且没有原图的战绩无法从日志还原。

跨屏字体自适应通常在移动结束后约 0.25 秒内更新，也支持同屏更改 Windows 缩放比例。界面缩放跟随软件窗口所在屏幕，设置中的“游戏所在显示器”仍单独控制截图来源。字体按逻辑字号和屏幕缩放保持可读性；屏幕物理尺寸、像素密度及你设置的缩放比例不同，不能保证两屏上文字精确相同的厘米大小。最大化时保留最大化状态；内容超过工作区可滚动，不需要重启或手动改字号。

- 窗口模式采样单个游戏窗口，屏幕兼容模式要求 Apex 位于前台。只缓存一张最新窗口画面，不录制整段视频。
- 用缩小画面的“总结”“造成伤害”“击杀／助攻／击倒”布局寻找候选；完整 OCR 再校验页面文字。未通过校验的候选不计入，最近8张原图和OCR保存在数据目录的 `rejected-candidates` 文件夹，可用图片导入补录。继续检测时会短暂延后重试，减少同一失败画面重复处理。
- 启动后的首次总结可以作为中途启动的首局；之后识别到新局加载／选人组合证据才自动建立下一场比赛。选人检测要求至少四类标签出现在下方、最底部选人提示，以及左侧上半部选人控制同时成立；大厅单独的五类标签不够。加载检测要求模式、中央倒计时文字与数字、下方小队静音提示同时成立，不依赖地图或段位。
- 每约2秒在独立本地OCR执行器检查四块区域（一次OCR未结束时不另排任务）；总结页用快速模板候选检测。OCR忙时截图先写本地恢复队列；每个连续总结页最多保留3张不同像素原图，补拍间隔8秒。短暂非总结／模板失败容忍12秒，超过才结束当前截图片段，不创建新比赛；标签切换、重开总结、换屏、切出本身不代表新局。
- 新局证据开启周期；总结候选落盘暂时关闭，完整OCR通过后确认结束；拒绝且没有成功结果时回滚。重复加载／选人动画、尚未结束周期内的重连／重选不新建比赛；等待下一场期间重新打开旧总结，完全相同像素直接复用原记录。Beta6对刚结束的同一总结返回做保守视觉比对；不能证明同页、又没有观察到新局开始时，仍保存原图，显示“未观察到新局开始”，请在“查看 / 修正”中选择“确认是新的一局”或“归入已有比赛”。这条审核路径防止不确定时丢局，也防止按数字猜着合并。
- 备用入场证据使用初始运输船：跳伞指挥官、单独发射、运输船操作及罗盘的组合，两次探测间隔至少2秒。单纯战斗、小队数、伤害数字或观战HUD不建立新比赛。手动确认后，同片段副本更新并收起，冲突的人工归属不擅自覆盖。
- 选人识别提供简／繁中文和英文关键词，但当前总结模板及数字OCR路径主要验证中文大逃杀界面。其他语言、外卡同时选人、娱乐重选、重连和季节布局变化没有完整实机覆盖，不能保证这些模式完全自动；请保留快捷键补录。研究没有获得可逐帧验证的S30全模式素材，详细缺口列在 RESEARCH.md。


程序不会帮你点击“总结”或操作游戏；游戏没有显示总结页、停止渲染、停留太短或界面未加载完整时，不能保证捕获。后台 OCR 在本机样例上约 2–6 秒，期间可继续游戏；识别不确定时仍需要稍后确认。

人数在开始记录时固定。名单确定后在本次记录内固定；需要更换队友或人数，结束后开始新记录。旧历史及已在进行的旧版记录保留原名单；新逻辑从新开的记录生效。自动识别的昵称和显示名称按记录保存，新队友不会覆盖旧历史中的名字。

例如双人模式：第一局 A/B/C、第二局 A/B/D，确定 A 与 B 并补算两局。如果两局都是 A/B/C，仍有三位候选，会等待第三局、第四局……直到共同昵称恰好为两位，或者由你手动确认。单人模式同理，需要共同昵称恰好为一位。重复截图不作为另一局的推断证据。昵称缺失、置信度不足或无法区分时，不用该截图缩小候选名单；可以检查昵称绑定或手动确认。

如果你已在设置绑定自己的实际识别昵称，单人模式下该昵称在两场不同比赛中均被可靠读出，即使某局路人昵称未读全，也可按已有绑定确定你并补算；双人模式需两位已绑定玩家都可靠重复出现。可靠共同候选超过所选人数、完整名单仍有歧义、绑定冲突或同页重复时，继续等待。尚未绑定的身份仍需要完整昵称对比；状态会说明有几局昵称未读全。已确认的手动修正不会被启动补算覆盖。

统计格式（根据人数显示一至三行）：

```text
共计：X 场游戏
玩家：显示名称  伤害：XXX  击杀：XXX  助攻：XXX  场均伤害：XXX.X  参团率：XX.X%
玩家：显示名称  伤害：XXX  击杀：XXX  助攻：XXX  场均伤害：XXX.X  参团率：XX.X%
玩家：显示名称  伤害：XXX  击杀：XXX  助攻：XXX  场均伤害：XXX.X  参团率：XX.X%
```

场均伤害 = 总伤害 ÷ “共计”中的已确认总场数，保留一位小数；用橙黄色区分其他三个白色数据。身份尚未确定或零场时显示“—”；待确认截图不进入分母。修正数据或忽略记录后，场均伤害一起重算。

游戏把昵称字符显示成方框时，程序无法还原原字。自动确定后默认显示 **OCR 实际读出的昵称**；可以在“设置”填写完整显示名称。方框也可能被 OCR 读成“口”等字符；以实际识别结果绑定。两个昵称无法区分时，必须手动选择归属，程序不会猜人。也可以在设置的匹配昵称框中维护同一玩家的多个实际读法，每行一个。

## 自定义截图快捷键

在“设置 → 截图快捷键”输入组合键，如 `Ctrl+End`、`Ctrl+Alt+F8`、`Shift+Home`。支持 Ctrl／Alt／Shift／Win 修饰键，以及 End、Home、PageUp、PageDown、方向键、Insert、Delete、Space、Pause、ScrollLock、字母、数字、F1–F24（除系统保留的 F12）。保存时实际尝试系统注册；无法注册会提示并保留原设置。自定义设置会持久保存。

快捷键只在正在记录时注册，结束记录或退出程序时释放。Ctrl+End 在编辑器中常用于跳到文末；记录过程中会被本程序作为全局截图键占用。“检查占用”只能检查当前 Windows 全局注册状态，无法检测其他应用内部的快捷键或自定义游戏键位。[Microsoft 快捷键说明](https://support.microsoft.com/en-us/accessibility/windows/keyboard-shortcuts-in-windows)、[RegisterHotKey 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。

EA 公布的默认 Apex 键位表没有列出 Ctrl+End，但 Left Ctrl 用于按住蹲下；如果自行绑定过 End，请在游戏中核对。[EA 按键与修改方法](https://help.ea.com/en/articles/apex-legends/pc-and-controller-settings/)。本次更新将首版的默认 Ctrl+Alt+F8 改为 Ctrl+End，其他已保存的自定义快捷键保留。

## 截图与识别时间

自动模式每秒约检查两次；总结页至少可见1.5秒，且“小队总击杀”文字、数字出现并稳定至少1秒，再连续取候选进行捕获。已完整显示的页面通常约2秒可保留，加载较慢则继续等待，以“完整画面已保留”提示为准；不必等后台OCR结束。手动模式需要等总结页完整显示再按键，**听到“截图已保存”提示音就能继续游戏**。本机真实图片识别实测约 2–6 秒，具体受电脑性能、分辨率和界面影响。后台识别期间再次按快捷键会被忽略，避免重复手动截图；自动检测仍可保留下一张候选。

## 修正、重复记录与历史

- 身份未确定时保留原图与每局结果，暂不累计。确定后，只有参与玩家的数据全部确认才计入“共计 X 场”；1 人模式只需一人的数据，2 人模式只需两人的数据。路人数据无需填写；未读出的字段不会当作 0。
- 双击历史记录或点“查看 / 修正”，可修改玩家归属和数字；保存会替换旧值并重新累计，场数不会多算。
- 同一次记录内，像素完全相同的截图会直接找到原记录，不重复 OCR、不增加历史或场数、不重复弹出确认。导入、快捷键和关闭重开后的处理相同；原有手动修正保留。
- 手动截图／导入的去重依据是整张截图解码后的RGB像素与尺寸；文件名、PNG压缩方式或元数据不同不影响判断，JPEG有损压缩造成像素变化则视为不同图像。不同图像不会只因OCR数字相同而合并。自动捕获保存独立比赛编号；同一明确周期内的多张不同图像都作为证据保存，随后收起副本、只累计一次。Beta6增加下文的总结返回视觉规则；其余没有新局证据的变化进入比赛归属审核。只比较同次开黑记录，不跨会话去重。
- 校正并保存后，像素完全相同或已明确核实为同一局的其他副本会从列表收起，只累计一条，优先保留手动校正结果。原始记录、每份数据与照片保留；不会按数值或时间接近批量猜测旧记录属于同一局。启动时整理已证实副本，并补算可靠待确认局，不覆盖已保存手动值。历史中曾手动明确选择“属于新的一局”的记录保持原选择。
- 新版模型就绪后，后台优化当前历史中旧版的识别结果，并补算达到要求的待确认局；原有已确认数据和手动修正保留。选择其他历史也会检查一次。主窗口“重新识别待确认”可再次尝试仍未确认的原图；没有原图则无法重读。
- 击杀行的斜杠误读为数字时，尝试按橙色分隔符几何位置拆成三项独立识别；低置信伤害尝试灰度和反色复读，两次均高置信且一致才采用，不降低原识别门槛。没有可靠结果时仍保留待确认。
- 参与玩家的伤害／击杀／助攻恰好与另一局相同，不再触发重复提示或阻止自动累计。数字均为0的不同图像也可以分别计入场数，场均伤害随场数重算。
- “忽略这张截图”会移出统计，原图仍保留。再次导入相同截图会提示已忽略；打开原历史的“查看 / 修正”，点“恢复为待确认”，核对后保存，无需再造一条记录。
- 顶部下拉框可查看以往开黑记录。关闭后重新打开会恢复未结束的统计。
- “导入截图”可读取 PNG、JPEG、BMP、WebP 文件，适合补录或退出游戏后离线统计。

## 本地数据

默认保存于 `%LOCALAPPDATA%\ApexSessionTracker`，通常是 `C:\Users\你的用户名\AppData\Local\ApexSessionTracker`：

- `tracker.sqlite3`：设置、昵称绑定、每局记录与统计；
- `screenshots`：原始截图；
- `app.log`：错误日志；
- `capture-spool`：尚未提交数据库的恢复证据（非一分钟录像）；
- `backups/before-v14.sqlite3`：首次迁移前的一致数据库备份。

“设置 → 打开数据目录”可以找到数据库和日志。备份时先关闭程序，再复制整个数据目录；如果更改过照片位置，也要复制相应照片文件夹。

## 照片位置与磁盘清理

在“设置 → 照片存储 → 选择照片位置”选择文件夹，程序在其中创建 `ApexTrackerScreenshots` 专用子目录；点“保存设置”后生效。仅之后的新照片写入该位置，已保存原图继续从原路径读取，不自动搬移。路径不可用时临时回退默认位置并显示提示。

结束记录并等待识别完成后，打开“设置 → 清理照片与数据”。可以先看张数、预计释放空间和待确认数量，再执行并确认清理范围：

- **清理重复照片与日志缓存**：删除已合并的副本和专用目录内未关联记录的程序照片，保留每局主图和战绩。
- **清理全部照片与日志缓存**：保留战绩、玩家和设置，之后仍能查看数字、修正数据，但不能查看或重新识别已删原图。
- **清空全部战绩、照片与日志**：删除所有会话与每局统计，保留玩家绑定、快捷键、人数模式和照片位置设置。

清理只删除已登记管理目录中的程序 UUID PNG 和程序自己的日志，不递归清空所选文件夹，不删除其他文件或 OCR 模型。无法删除的文件会保留并显示失败数量。删除不可撤销；需要留原图的待确认局，先核对或备份。照片清理和历史清空需要用户手动执行，后台不会自动删原图。

## 使用边界与常见问题

程序使用系统屏幕捕获、公开窗口标题／位置查询和 `RegisterHotKey`，仅对截图执行本地分析。没有游戏内存读写、DLL 注入、游戏文件修改、自制驱动、游戏自动操作或反作弊绕过功能。**这不代表 EA 官方许可，也不能保证零误判或零封禁。** 已被动获取正在运行的 Apex 窗口画面；这不等于得到反作弊许可或完成长期兼容验证。

- 快捷键被占用：在设置中换一个组合键，F12 是系统保留键，不能使用。
- 截到错误屏幕：在设置中选择游戏显示器。
- 截图黑屏或数据没显示完整：不要直接保存猜测数据；尝试游戏的无边框窗口显示方式，或使用现有截图功能保存图片再导入。无法识别时可手动填写。
- 游戏更新改变总结布局：可能导致待确认增多。保留新截图以便调整识别逻辑。
- 程序已在运行：同一个数据目录只允许启动一个实例。

## 参团率与总结返回（Beta 6）

- 单局参团率＝（该玩家击杀＋助攻）÷该局完整小队总击杀；累计参团率＝所有已确认比赛个人击杀与助攻之和÷这些比赛小队总击杀之和，不是单局百分比的平均。示例：两局分别2/6、12/20，累计14/26＝53.8%。单／双人统计的分母也包括路人击杀。
- 只读取总结页明确显示的“小队总击杀”文字及其数值，绝不把三位玩家击杀相加作为分母。总击杀与个人卡片击杀之和不同，也仍按显示的总击杀计算；不会用相加结果覆盖或否决它。标签／数值未读出、低置信或多个头部读数矛盾时待确认。分母总和为零显示“—”；任一有效比赛缺分母时，累计显示“—”并说明缺几局，不暗中计算部分比赛的百分比。其余统计照常记录。
- “查看 / 修正”可取消自动读取并填写小队总击杀；未知留空，重新选择自动读取可撤销手动分母。个人数据与小队分母可分别修正，累计随保存即时更新。每局历史文字包含个人参团率。
- 截图精确去重仍用完整RGB＋尺寸哈希。另对前一局刚结束、120秒内返回的自动总结做视觉比对：三张卡片所有明亮文字像素（昵称和完整数据区）在20灰阶以内一致，并至少两块独立卡面有99%以上像素在同样容差内一致；不比较排队框、字幕、世界背景。时间仅是拒绝边界，不能证明同局；只有数值相同不会通过。固定分辨率与完整三卡是当前边界。
- 若期间观察到新局开始、出现另一张不一致的总结、人工明确另开一局或仍在忽略状态，则阻止这条自动归并。通过的副本保留原图和判定依据，从列表收起，保留人工修正，只计一次。无法确定仍待审核；公开画面不足以保证区分所有漏开局且视觉完全相同的真实比赛。
- 升级前自动使用SQLite一致备份（schema17）；旧版相加分母自动失效，既有OCR文字中明确的头部可补算分母，无须批量重读照片。程序启动整理已证实副本，但保留用户之前的人工处置；请先关闭旧版再启动新版。

## 总结加载完成后再读取（Beta7）

自动模式先识别总结候选，再检查总击杀标签及黄色数字（0也有效）出现并保持稳定。加载等待不会占用三张正常OCR候选额度；稳定后取完整画面，保留就绪依据。若过早离开或停止，只保留一张未完整候选供恢复，不将它自动确认为一局。后来出现完整画面时，同局副本归并并优先处理完整候选；完全相同像素再次被观察为稳定时，只升级就绪依据，不重复OCR／累计。

个人数字可靠但没有明确总击杀的新识别结果，也不会自动计入；可稍后补拍、导入完整截图，或在修正窗口对照完整总结手动填写小队总击杀。已确认的旧个人战绩不删除，旧推算分母不再使用：任何有效局缺少真实分母，累计参团率显示“—”并提示缺几局。

累计仍严格使用Σ个人（击杀＋助攻）÷Σ各局明确小队总击杀；单局使用当局显示值。完整显示的0是合法分母记录，不误认为识别失败；除数为0时只显示“—”。
